# תהליך יצירה ועדכון של דף נחיתה

## גבולות אחריות

| החלטה או נתון | מקור אמת |
| --- | --- |
| מודל תוכן והגדרות אתר של EmDash | EmDash CMS |
| נוסח, הצעה ומדיה המוצגים בדף | רשומת EmDash באוסף `landing_pages` |
| מוצר, קהל, עיצוב וכללי כתיבה עבור הסוכן | רשומות טיוטה באוסף `agent_context` |
| קוד תצוגה, רכיבים, routing ואינטגרציות | ה־repo |
| הגדרות Worker, bindings וסודות | `wrangler.json` ו־Cloudflare secrets |
| נימוק היסטורי להחלטות | `docs/landing-pages/<slug>/decisions/` |

ההקשר הפעיל ותוכן הדף אינם נשמרים כעותק Markdown ב־repo. עד שהעברת ההקשר ל־EmDash הושלמה ונבדקה, קובצי ההקשר המקומיים מסומנים כחומר מעבר בלבד; אם חסרה רשומת הקשר ב־CMS, עוצרים לפני יצירת תוכן חדש.

## יצירת דף

1. קראו את `.agents/skills/emdash-cms-management/SKILL.md` ואת החלטות העיצוב/המוצר ההיסטוריות הרלוונטיות.
2. דרך EmDash MCP או API מאומת, בדקו את הסכמה החיה ואת קיום `landing_pages` ו־`agent_context`. צרו את רשומות ההקשר כטיוטות ורק אחרי אישור התוכן והמודל.
3. טענו את כללי הכתיבה הגלובליים ואת רשומות המוצר, הקהל והעיצוב של ה־slug המבוקש. אל תסיקו מחיר, הוכחה, הבטחה או יעד מסחרי שחסרים בהקשר.
4. צרו את רשומת `landing_pages` בטיוטה, תוך שימוש רק ב־block types והשדות הקיימים בסכמה ונתמכים ב־`src/components/landing/EmDashLandingPage.astro`.
5. העלו מדיה דרך EmDash, בדקו תיאור חלופי, שמרו טיוטה וקראו אותה בחזרה. השתמשו ב־preview של EmDash ובדקו RTL, מובייל, נגישות ויעדי קישור.
6. פרסמו רק כשהמשתמש ביקש במפורש שהשינוי יהיה חי. לאחר פרסום, בדקו את הכתובת הציבורית.

## עדכון דף קיים

1. סווגו את השינוי: תוכן, הקשר מוצר/קהל/עיצוב, מודל CMS, renderer או תצורת פריסה.
2. לשינוי הקשר: עדכנו את רשומת `agent_context` המתאימה כטיוטה וקראו אותה בחזרה לפני יצירת תוכן שתלוי בה.
3. לשינוי תוכן: קראו את הרשומה, הגרסה החיה, הטיוטה והסכמה; ערכו רק את השדות הנדרשים, שמרו טיוטה ובדקו preview.
4. לשינוי סכמה או renderer: שנו את מודל EmDash דרך CMS ואת המימוש ב־repo באותה עבודה; בדקו שהשדות והבלוקים שה־renderer צורך תואמים לסכמה החיה.
5. שמרו החלטות מתמשכות בתיקיית `decisions/` לאחר אישורן. החלטה ישנה שהוחלפה נשארת היסטורית ואינה מקור פעיל.

## בדיקות מסירה

- `npm run docs:check` עובר; הוא בודק את מפת העמודים המקומית בלבד.
- `npm run check` עובר עבור תיעוד ה־repo, build, TypeScript ו־Cloudflare dry run.
- EmDash מאשר את הסכמה והטיוטה; הסוכן קורא את השינוי בחזרה ומשווה ל־live revision.
- EmDash preview והעמוד הציבורי (לאחר פרסום מפורש) נבדקו ב־RTL, מובייל, מקלדת, נגישות וקישורים.
- לא מוצגים placeholders, מחירים לא מאושרים, עדויות ללא רשות או הבטחות תוצאה לא מבוססות.
