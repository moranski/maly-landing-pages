# תהליך יצירת דף נחיתה

מסמך זה מתאר את סדר העבודה המחייב ליצירת דף נחיתה חדש ולעדכון דף קיים. לכל דף יש תיקיית workflow משלו, ולכן מוצר, קהל ועיצוב אינם מנוהלים בשכבה משותפת בין דפים.

## מקורות אמת

| החלטה | מקור אמת |
| --- | --- |
| כללי כתיבה והבטחות | `docs/writing-style.md` |
| הגדרת המוצר וההצעה | `docs/landing-pages/<slug>/product.md` |
| קהל, בעיה ומסר | `docs/landing-pages/<slug>/audience.md` |
| שפה חזותית ורכיבי ממשק | `docs/landing-pages/<slug>/design.md` |
| תוכן, הצעה ופרטי עמוד מסוים | קובץ ה־MDX ב־`src/content/landing-pages/` |
| הנימוק להחלטות קבועות | רשומה מתאימה ב־`docs/landing-pages/<slug>/decisions/` |

במקרה של סתירה, לא משנים את העמוד כדי לעקוף אותה. מעדכנים קודם את מקור ההחלטה המתאים, ולאחר אישור מעדכנים את הקוד או התוכן.

## יצירת דף חדש

1. בוחרים `slug` יציב ויוצרים את `docs/landing-pages/<slug>/`.
2. יוצרים בה את `README.md`, `product.md`, `audience.md`, `design.md` ואת תיקיית `decisions/`. אפשר להתחיל את `design.md` מ־`docs/templates/landing-page-design.md`.
3. מתעדים החלטות בעלות השפעה מתמשכת באמצעות `docs/templates/decision.md` בתוך `decisions/` של אותו דף.
4. מגדירים קישורים הדדיים בין המוצר, הקהל, העיצוב וה־MDX הפעיל.

## יצירת עמוד מקובץ הבסיס

1. קוראים את `docs/writing-style.md`, ובפרט את המטא־תבנית המחייבת לדפי נחיתה, ואת מקורות האמת בתיקיית הדף.
2. מעתיקים את `docs/templates/landing-page.mdx` לקובץ חדש תחת `src/content/landing-pages/` ומשנים את `slug` ואת המטא־דאטה.
3. מחליפים את תוכן הדוגמה בתוכן שמבוסס על מקורות האמת. לא משאירים placeholder, נתון לא מאומת או יעד רכישה לדוגמה בעמוד שאינו טיוטה.
4. משתמשים ברכיבים קיימים. צורך קבוע חדש ברכיב, בטוקן או בשדה מתועד במקור האמת העיצובי; פרטי מימוש זמניים נשארים במשימה או ב־PR ואינם הופכים למסמך קבוע.
5. מעדכנים את מקור האמת לפני העמוד אם במהלך העבודה מתברר שחסרה החלטת מוצר, קהל או עיצוב. אם השינוי מהותי, מוסיפים גם רשומת החלטה.
6. מריצים `npm run check` ובודקים ידנית RTL, מובייל, נגישות והמרה.

בעת מילוי קובץ הבסיס, עוברים על כל 14 המקטעים במטא־תבנית. אם מאחדים מקטעים או משמיטים מקטע, מוודאים שההחלטה תואמת למוצר ולקהל ושאין צורך חסר בפרט מאושר, כגון עדות, מחיר או בונוס.

## עדכון עמוד קיים

1. מזהים מהו סוג השינוי: מוצר, קהל, עיצוב, כתיבה כללית או ניסוח מקומי לעמוד.
2. מעדכנים תחילה את מקור האמת המתאים. ניסוח מקומי שאינו משנה החלטה יכול להתעדכן ישירות ב־MDX.
3. כאשר החלטה קיימת משתנה, יוצרים רשומה חדשה, מסמנים את הישנה כ־`הוחלפה` ומקשרים ביניהן.
4. מעדכנים את הקוד ואת ה־MDX, ואז מבצעים את בדיקות המסירה.

## מחקר וחומרי ייחוס

חומרי ייחוס משמשים להבנת המוצר, השוק או השפה הקיימת. הם אינם הוראת כתיבה, אינם מקור להבטחות, ואינם מיועדים להעתקה.

חומר מחקר זמני נשמר מחוץ לתיעוד הקבוע ונמחק לאחר שההחלטות הרלוונטיות הועברו לרשומת החלטה ולמקור אמת. אין לשמור צילום מסך, סיכום מתחרה או תוכנית יישום כאילו הם הנחיה פעילה.

## בדיקת מוכנות לפני יישום

לפני תחילת פיתוח ודאו:

- למוצר, לקהל ולספר העיצוב יש מקור אמת פעיל.
- טווח הגיל, המוצר, מסלול הרכישה והנכסים זמינים וברורים.
- מחיר, מבצע ותוקף קיימים רק אם אושרו עסקית.
- לכל עדות יש אישור שימוש, שם או אופן אנונימיזציה מאושרים.
- אין הבטחות מוחלטות, טענות אבחוניות או טענות תוצאה שאינן מבוססות.

## בדיקות מסירה

- `npm run content:check` עובר.
- `npm run docs:check` עובר ללא שגיאות.
- `npm run build` עובר.
- העמוד נבדק במובייל ובמסך רחב, ב־RTL ובמקלדת.
- הצבעים, הטיפוגרפיה והתמונות עומדים בספר העיצוב.
- המסך הראשון מבהיר למי הדף מיועד, מהו הקושי ומהי הפעולה הבאה.
- כל 14 המקטעים במטא־תבנית קיבלו מענה, אוחדו במכוון או סומנו כלא רלוונטיים.

## ניקוי בסיום העבודה

- מוחקים תוכניות יישום, סיכומי ביניים וטיוטות שאין להן ערך היסטורי עצמאי.
- לא יוצרים עותקים כגון `final`, `final-2`, `old` או קובץ מתוארך של מקור אמת.
- משאירים רשומות החלטה שהתקבלו או הוחלפו בתוך תיקיית הדף, משום שהן מסבירות את ההיסטוריה; רשומה שהוחלפה אינה מקור אמת פעיל.
- בודקים את `docs/README.md` ומעדכנים אותו רק כאשר נוסף סוג תיעוד חדש או השתנה מיקומו.
