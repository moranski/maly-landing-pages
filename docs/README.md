# מפת התיעוד

התיקייה `docs/` מחזיקה שני סוגי מידע בלבד: מצב נוכחי והיסטוריית החלטות. ההפרדה ביניהם נועדה למנוע מצב שבו תוכנית עבודה ישנה או בריף זמני נתפסים בטעות כהנחיה פעילה.

## מקורות האמת הפעילים

| נושא | מיקום | מה נשמר בו |
| --- | --- | --- |
| מוצר נמכר | `docs/products/` | מה נמכר, מה כלול, מנגנון, גבולות ופרטים מסחריים מאושרים |
| קהל יעד | `docs/audiences/` | מי הקהל, באיזה מצב הוא נמצא, מה מניע אותו ומהו השינוי הרצוי |
| עיצוב | `docs/design-systems/<id>/DESIGN.md` | טוקנים, שפה חזותית, מבנה, רכיבים וכללי שימוש |
| כתיבה | `docs/writing-style.md` | כללי הטון, הניסוח וההבטחות שחלים על כל הפרויקט |
| עמוד פעיל | `src/content/landing-pages/` | הנוסח וההצעה שמוצגים בפועל בכל עמוד |
| נתונים לקוד | `src/content/landing-page-families.ts` | שדות מובנים שנחוצים ליישום ולבדיקות בלבד |

לכל מוצר וקהל יש קובץ מקור אמת יחיד. לכל מערכת עיצוב יש תיקייה ובתוכה `DESIGN.md` יחיד. מעדכנים אותם במקום ליצור גרסאות כגון `final`, `new` או קבצים עם תאריך בשם.

## היסטוריית החלטות

רשומות ב־`docs/decisions/` מסבירות למה התקבלה החלטה ומה היא שינתה. הן אינן משכפלות את כל המצב הנוכחי ואינן גוברות על מקורות האמת הפעילים.

כאשר החלטה משתנה:

1. יוצרים רשומת החלטה חדשה ומציינים איזו רשומה היא מחליפה.
2. מסמנים את הרשומה הקודמת כ־`הוחלפה` ומקשרים לחדשה.
3. מעדכנים את מקור האמת הפעיל באותה עבודה.
4. מעדכנים את העמוד או את הקוד רק לאחר שמקור האמת מעודכן.

## תהליך וקובצי בסיס

- `docs/workflows/landing-page-creation.md` — סדר העבודה מפתיחת מקורות האמת ועד למסירה.
- `docs/templates/landing-page.mdx` — קובץ הבסיס לעמוד נחיתה חדש.
- `docs/templates/DESIGN.md` — קובץ הבסיס למערכת עיצוב חדשה.
- `docs/templates/decision.md` — קובץ הבסיס לרשומת החלטה חדשה.

`npm run design:check` בודק את כל קובצי `DESIGN.md` הפעילים, ו־`npm run check` כולל אותו כחלק מפלייבוק המסירה.

תוכניות יישום זמניות, סיכומי מחקר וטיוטות אינם נשמרים כתיעוד קבוע. אם יש בהם החלטה ארוכת טווח, מעבירים אותה לרשומת החלטה ולמקור האמת המתאים; אחרת מוחקים אותם בסיום העבודה.
