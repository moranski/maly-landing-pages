# טעינת דפי הנחיתה

הדוח מ־13.10.2026 בדק תצוגת טיוטה של `/reading` במובייל: ביצועים 88, ‏FCP ו־LCP של 3.1 שניות, ‏CLS אפס ו־TBT אפס. ממצא נגישות נוסף זיהה שם נגיש שאינו כולל את כותרת הדף הגלויה בקישור המותג.

`LandingFonts.astro` מגיש Rubik מקומי בשני קובצי WOFF2 משתנים, עברית ולטינית, עם `font-display: swap` וטעינה מוקדמת של עברית. הקבצים והרישיון נמצאים ב־`src/assets/fonts/`. כדי לעדכן את הפונט, יש לשמור גם את טווחי התווים המתאימים להגדרות `@font-face`.

הגדרת Vite מטמיעה ב־HTML קובצי CSS קטנים מ־40KB בלבד; הפונטים, התמונות וה־CSS הגדול של ממשק הניהול נשארים קבצים נפרדים.

`src/lib/landing/media-images.ts` יוצר כתובות עבור מנגנון `/_image` המובנה ב־EmDash וב־Cloudflare. הוא מקטין תמונות מקומיות ומגיש WebP באיכות 85. מנגנון זה משתמש ב־Images binding שכבר מופיע בהגדרות הבנייה. תמונות חיצוניות ואיורי SVG נשארים בכתובות המקור שלהם. בפיתוח נשמרות כתובות המקור, כי סביבת המדיה המקומית אינה מכילה את ספריית המדיה של האתר החי.

ה־renderer מעביר רק מידות מספריות תקינות מתוך שדות המדיה של EmDash. `srcset` מוגבל לרוחב המקור, כי Images אינו מגדיל תמונות. כשמידות המקור אינן ידועות, נוצרת כתובת יחידה בלי תיאורי רוחב שעלולים להיות שגויים. `sizes` תואם למדידות רכיבי הגלריה והפתיחה בדפדפן.

רקע הדף שומר על מקורו ב־EmDash ועל מידות 724×2172, עבור אריח של 362×1086 פיקסלים ב־CSS. בדיקת מנגנון ההגשה הקיים החזירה WebP של 121,856 בתים לעומת PNG של 1,572,858 בתים — הפחתה של כ־92%. כרטיס לימוד ברוחב 320 החזיר 13,966 בתים, ודיוקן ברוחב 168 החזיר 4,742 בתים. אלה מדידות של וריאציות התמונה, ולא ציון Lighthouse חדש של המימוש.

האימות כולל בדיקות יחידה למידות ולכתובות המדיה, `npm run check`, ובדיקת דפדפן ב־320, 390, 768 ו־1440 פיקסלים: טעינת הפונט המקומי, ללא פניות ל־Google Fonts, ללא גלילה אופקית או שגיאות JavaScript, ופתיחת שאלה נפוצה. יש להריץ Lighthouse באותם תנאים אחרי פריסת המימוש כדי למדוד FCP ו־LCP מחדש.
