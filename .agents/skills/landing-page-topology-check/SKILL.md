# בדיקת טופולוגיה של דף נחיתה

בדקו קריאה בלבד. אין לשנות תוכן CMS, schema או קוד במסגרת audit אלא אם המשתמש ביקש במפורש גם לתקן.

## איתור וחיבור

1. זהו את ה־`slug` המבוקש או הסיקו אותו מ־`docs/landing-pages/<slug>/README.md`.
2. קראו את מיומנות EmDash ב־`.agents/skills/emdash-cms-management/SKILL.md` לצורך חיבור בטוח וקריאה של רשומות CMS.
3. קראו דרך MCP/API מאומת את הסכמה החיה, רשומת `landing_pages` המתאימה, ואת רשומות `agent_context` הגלובליות והייעודיות לדף. התייחסו להחלטות בקבצי `decisions/` כהיסטוריה; מקור ההקשר הפעיל הוא EmDash.
4. אם אין חיבור או שרשומת הקשר חסרה, דווחו אילו מעברים לא ניתן היה לבדוק. אין להסיק שתוכן ה־CMS תואם מתוך קובץ מקומי או מפת דף.

## סדר הבדיקה

```text
הקשר הגלובלי + הקשר הדף ב־EmDash
                  ↓
       schema + landing_pages entry
                  ↓
          renderer ו־route ב־repo
                  ↓
            preview / דף חי
```

## מה מאמתים

- **הקשר:** כתיבה, מוצר, קהל ועיצוב אינם סותרים זה את זה. אין טענות, מחירים או עדויות ללא אישור במידע הזמין.
- **schema → entry:** ה־slug, מטא־נתונים, block types, גרסאות, שדות ומדיה תואמים לסכמה החיה. בדקו שהקשר נשאר טיוטה ושדף התוכן במצב הצפוי.
- **entry → renderer:** כל block type וכל שדה נצרכים על ידי `src/components/landing/EmDashLandingPage.astro` או מטופלים במפורש. בדקו סדר, קישורים, תמונות, `alt`, RTL והתנהגות CTA.
- **renderer → result:** השתמשו ב־EmDash preview לרשומה לא מפורסמת; אם הרשומה מפורסמת, בדקו גם את הכתובת הציבורית. אל תפרסמו או תשמרו שינויים.
- **repo map:** הריצו `npm run docs:check` כדי לוודא שמפת הדף המקומית קיימת. בדיקה זו אינה קוראת או מאמתת את EmDash.

## דיווח

הציגו מסקנה קצרה ואז ממצאים לפי חומרה: חוסם, דורש החלטה או תחזוקה. לכל ממצא ציינו את מקור האמת, המעבר שנבדק, ההבדל ובעל התיקון הנכון. ציינו בנפרד כל schema, CMS record, preview או route שלא נגישו.

אל תדווחו על התאמה כוללת כאשר EmDash לא היה נגיש. במקרה כזה, השלימו רק את בדיקת ה־repo ודווחו שהאימות מול התוכן וההקשר ב־CMS נותר חסר.
